# 🧠 트러블슈팅

특히 YOLO 모델의 추론 지연, 하드웨어 제어 타이밍 문제, PID 튜닝 과정에서 여러 시행착오가 있었습니다.
아래는 그중 대표적인 사례를 정리한 내용입니다.

## ⚡ 1. YOLOv5 추론 속도 저하
###  문제 상황
초기에는 YOLOv5s(.pt) 모델을 사용했는데,
라즈베리파이에서 평균 추론 속도가 **0.3~0.7 FPS** 수준으로 너무 느렸습니다.
ROS2 토픽 `/yolov5_ros2/object_detect`의 평균 rate를 보면 프레임 간격이 10초가 넘는 경우도 발생했었습니다.

```
average rate: 0.352 min: 0.352s max: 12.691s std dev: 3.93s window: 8
average rate: 0.417 min: 0.338s max: 42.267s std dev: 7.41s window: 33
```
YOLO 노드의 결과가 늦게 들어오다 보니
차선 인식과 객체 인식 타이밍이 엇갈리고,
횡단보도나 신호등을 인식했을 때 이미 지나쳐버리는 문제가 생겼습니다.

### 시도한 방법
1. `max_queue_size`를 2 → 1로 줄였지만 FPS 변화 거의 없음
2. ROS2 `MultiThreadedExecutor` 적용 — 병렬 구조 개선했지만 CPU 병목 그대로
3. YOLOv5n 모델로 교체 — 속도는 조금 빨라졌지만 정확도 급감
4. YOLOv5s(320) 리사이즈 — 연산량 줄어도 지연 지속
5. 마지막으로 `.onnx` 변환 및 `onnxruntime` 적용

### 해결
PyTorch 기반 동적 그래프를 정적 그래프로 바꾼 ONNX 모델이 결정적인 해결책이었습니다.
FPS가 약 **0.5 → 1.6Hz**로 3배 이상 상승,
객체 인식–제어 간 지연이 1초 이내로 줄었습니다.
```
average rate: 1.472 min: 0.385s max: 0.899s std dev: 0.15s window: 35
average rate: 1.721 min: 0.377s max: 0.899s std dev: 0.17s window: 56
```

## 💡 2. LED 제어 지연 및 중복 점등
### 문제 상황
주행 상태를 표시하기 위해 LED를 사용했는데, 간헐적으로 깜빡임 주기가 엉키거나 정지 상태인데 초록불이 계속 들어오는 문제가 있었습니다.

원인은 LED 명령을 퍼블리시하는 토픽이 주기적으로 중복 호출되면서,
이전 상태를 덮어쓰는 현상이었습니다.

### 해결 방법
- LED 노드를 Timer 기반으로 주기 실행하도록 변경
- blink_state 변수를 두어 한 주기마다 명확한 ON/OFF 토글 수행
- ROS2 메시지 타입을 std_msgs/Bool로 단순화해 신호 혼선을 방지
```
def blink_led(self):
    self.blink_state = not self.blink_state
    msg = Bool()
    msg.data = self.blink_state
    self.publisher_.publish(msg)
```

## 🧭 3. PID 제어 불안정
###  문제 상황
초기 주행에서는 곡선 구간 진입 시 차량이 좌우로 흔들리며 차선을 이탈하는 현상이 자주 발생했습니다.

원인은 PID 파라미터 비율 불균형과 차선 오프셋 계산 지연이었습니다.

### 해결 방법
- P 값을 낮추고 D 항을 키워 과도한 반응을 줄임
- 오프셋이 커질수록 linear.x를 감소시키는 로직 추가
- lane_detect 콜백 주기를 고정(0.05초)해 타이밍을 일정하게 유지

튜닝 후에는 주행 곡선이 부드러워졌고, 차선 유지 오차가 ±3cm 수준으로 줄었습니다.
