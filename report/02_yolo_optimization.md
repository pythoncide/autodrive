# 🧠 YOLOv5 모델 최적화

## 🚩 배경

초기에는 YOLOv5s (.pt) 모델을 사용했지만, Raspberry Pi 4B의 CPU 환경에서 추론 속도가 매우 느렸습니다.  
ROS2 토픽 `/yolov5_ros2/object_detect`의 발행 주기가 평균 **0.3~0.7Hz** 수준이었고,
객체 인식–제어 간의 지연 때문에 실시간 주행이 불가능한 상태였습니다.
```
❯ ros2 topic hz /yolov5_ros2/object_detect
average rate: 0.352 min: 0.352s max: 12.691s std dev: 3.93s window: 8
average rate: 0.417 min: 0.338s max: 42.267s std dev: 7.41s window: 33
```

## 🔍 시도한 개선 과정
| 단계                     | 시도 내용                                 | 결과 요약                                 |
| ---------------------- | ------------------------------------- | ------------------------------------- |
| **① Queue 사이즈 조정**     | `max_queue_size`를 2 → 1로 축소           | 평균 FPS 소폭 향상 (0.82 → 1.15) / 근본적 개선 X |
| **② 멀티스레드 실행**         | `MultiThreadedExecutor` 적용            | 토픽 병렬 처리 성공, 속도 변화 거의 없음              |
| **③ 모델 교체 (YOLOv5n)**  | Nano 모델로 변경                           | 처리속도↑, 정확도↓ (차량/표지판 구분률 급감)           |
| **④ 해상도 축소 (320×320)** | YOLOv5s 입력 크기 축소                      | 연산량 감소 효과 미미, FPS 여전히 <1Hz            |
| **⑤ ONNX 변환**        | `.pt` → `.onnx` 변환 후 `onnxruntime` 사용 | **성능 대폭 향상 (약 3배 개선)**                |

## ⚙️ 최종 적용 모델: YOLOv5s (ONNX)
모델을 **.onnx** 형식으로 변환한 후, PyTorch 대신 onnxruntime 기반 추론을 사용했습니다.  
추론 그래프가 정적으로 최적화되어, Python 인터프리터 레벨의 오버헤드가 제거되었습니다.
```
❯ ros2 topic hz /yolov5_ros2/object_detect
average rate: 1.472 min: 0.385s max: 0.899s std dev: 0.15s window: 35
average rate: 1.721 min: 0.377s max: 0.899s std dev: 0.17s window: 56
```

## 📊 성능 비교 요약
| 항목     | `.pt (YOLOv5s)` | `.onnx (YOLOv5s)` | 개선율     |
| ------ | --------------- | ----------------- | ------- |
| 평균 FPS | 0.52 Hz         | **1.69 Hz**       | ▲ 225%  |
| 최소 지연  | 0.33 s          | **0.37 s**        | –       |
| 최대 지연  | 42.2 s          | **0.89 s**        | ▼ 97.9% |
| 표준편차   | 7.41 s          | **0.17 s**        | ▼ 97.7% |
| 인식 안정성 | 불안정             | 매우 안정           | -       |

- ONNX로 변환 후, 카메라 입력과 인식 결과 간의 동기화가 실시간 수준으로 맞춰졌습니다.  
- LED·PID 제어 노드 모두 정상 주기로 반응하며 전체 주행 안정성이 개선되었습니다.

## 🧩 분석
- CPU 환경에서 PyTorch 추론은 동적 그래프 구성으로 인한 메모리 낭비가 컸습니다.
- ONNX 변환을 통해 그래프를 정적으로 최적화함으로써 추론 효율이 향상되었습니다.
- 추론 속도만 개선된 것이 아니라 객체 인식–주행 명령 간 타이밍 불일치 문제도 함께 해결되었습니다.

## 📈 시각 비교
- `.pt` 모델 사용 시: 영상 프레임보다 인식 결과가 수초 지연되어 출력
- `.onnx` 모델 사용 시: 인식 결과가 1초 이내 주기로 안정 출력
```
Before (.pt)
 ┣━ Delay: ~8–12s
 ┗━ ROS2 avg rate: 0.4Hz

After (.onnx)
 ┣━ Delay: <1s
 ┗━ ROS2 avg rate: 1.6Hz
```

## 💬 회고
이번 개선 과정은 단순히 YOLO 모델의 크기를 줄이는 게 아니라, 추론 엔진 자체를 경량화하는 방향으로 접근한 것이 핵심이었습니다.  
결과적으로 ONNX Runtime 기반 모델이 정확도 손실 없이 실시간 주행이 가능한 최적 솔루션이 되었습니다.
